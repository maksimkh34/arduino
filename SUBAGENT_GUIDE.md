# SUBAGENT_GUIDE.md — Инструкции по работе субагентов

## 1. Проблемы с инструментами (Troubleshooting)

### Ошибка: JSON Parse error: Expected '}'
**Симптомы:** При использовании `write` или `filesystem_write_file` для записи больших файлов (глав), инструмент возвращает ошибку парсинга JSON.
**Причина:** Модель `omniroute/writer` некорректно формирует JSON-строку при больших объемах `content` или обрывает её.
**Статус:** ПОДТВЕРЖДЕНО в главе 1.1 (2026-06-03).

### ✅ РЕШЕНИЕ (ПРОВЕРЕНО): Использование Bash (PowerShell) с Add-Content
**Метод записи больших файлов (глав 50+ КБ):**

1. **НЕ ИСПОЛЬЗУЙ** `write` или `filesystem_write_file` для записи целой главы — это вызовет JSON-ошибку.
2. **ИСПОЛЬЗУЙ** PowerShell команду `Add-Content` для записи файла блоками.

**Пошаговый алгоритм:**

```powershell
# Шаг 1: Создать пустой файл
New-Item -ItemType File -Path "E:\arduino\chapters\NN-MM-title.md" -Force

# Шаг 2: Записать контент блоками через Add-Content
# Разбей главу на 8-12 частей (каждая ~50-100 строк или ~6-10 КБ)
Add-Content -Path "E:\arduino\chapters\NN-MM-title.md" -Value @'
Блок 1 текста главы (YAML front matter + начало)
'@

Add-Content -Path "E:\arduino\chapters\NN-MM-title.md" -Value @'
Блок 2 текста главы
'@

# ... продолжай для всех блоков

# Шаг 3: Проверь результат
Get-Item "E:\arduino\chapters\NN-MM-title.md" | Select-Object Name, Length
```

**Важно:**
- Используй `@' ... '@` (here-string) для многострочного текста в PowerShell.
- Не забывай экранировать ` как `` `$ `` внутри here-string, если текст содержит переменные.
- Каждый блок должен быть завершенным куском текста (не разрывай середину кода или таблицы).

**Проверено на главе 1.1:**
- Файл: `chapters/01-01-arduino-mega-first-contact.md`
- Размер: 78 271 байт (~78 КБ)
- Метод: 10 блоков через `Add-Content`
- Результат: ✅ SUCCESS

## 2. Отчетность при сбоях
Если инструмент выдает ошибку, субагент ОБЯЗАН:
1. Проанализировать текст ошибки.
2. Выдвинуть гипотезу (например: "Слишком большой объем данных для JSON").
3. Попробовать альтернативный метод (см. раздел 1).
4. Описать в финальном отчете, какой метод сработал.

## 3. Стандартный workflow написания главы

### Шаг 1: Прочитай опорные документы
```bash
- STATE.md (какая глава следующая)
- MASTER.md (описание главы)
- STYLE_GUIDE.md (стиль)
- GLOSSARY.md (термины)
- COMPONENTS.md (компоненты)
- SUBAGENT_GUIDE.md (этот файл)
```

### Шаг 2: Напиши главу в текстовом редакторе (в памяти)
Следуй канонической структуре из `WRITER_SYSTEM_PROMPT.md`.

### Шаг 3: Запиши главу через PowerShell блоками
Используй метод из раздела 1.

### Шаг 4: Обнови STATE.md
Добавь запись о главе, краткую выжимку, введенные понятия, следующую главу.

### Шаг 5: Обнови GLOSSARY.md (если нужно)
Добавь новые термины.

### Шаг 6: Git commit и push
После завершения главы:
```bash
git add chapters/NN-MM-title.md STATE.md GLOSSARY.md
git commit -m "Добавлена глава N.M: Название главы"
git push
```

### Шаг 7: Выведи отчет
Краткий отчет по шаблону из `WRITER_LAUNCH_PROMPT.md`.
